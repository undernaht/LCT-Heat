# 09. Промежуточная сдача: реализовано, риски, план

Формат по ТЗ §7.1: работающий прототип загрузки исходных данных,
автоматическое построение сети, краткий перечень реализованного, рисков и
плана до финала. Дата среза — 2026-09-20 (день получения ТЗ и датасета).

---

## 1. Что реализовано

**Загрузка исходных данных.** Один GeoJSON по §1 приложения принимается
через API (`POST /api/v1/projects`, потоком на диск) и через интерфейс.
Разбор сохраняет тип идентификаторов, переводит геометрию в EPSG:32637,
считает примыкания существующих камер, находит полигон каждой точки
подключения и отдаёт протокол разбора (что пропущено и почему). Типы
ограничений вне таблицы 2 не роняют расчёт, а помечаются.

**Автоматическое построение сети** — все 17 точек конкурсного набора за
один запуск, без ручной подготовки маршрутов:

| Что | Как | Где в коде |
|---|---|---|
| Выбор точек врезки | одна волна Дейкстры от каждой точки по полю стоимости в единицах S: сеть, существующие камеры (правило 10 м), уже построенные ветки | `route.py` |
| Совместное подключение | жадное дерево: ветка присоединяется к соседней, если это дешевле по S; общие участки возникают сами | `tree.py` |
| Расходы и Ду | сумма расходов ниже по дереву, минимальный Ду по таблице 1, неубывание к врезке, предельная длина по путям с поднятием только со стороны врезки, проверка минимальности | `diameters.py` |
| Геометрия | прямые участки, повороты ≤ 89,9° (запас к 90°), без огрызков и ступенек, финальный прямой участок от ближайшей границы ОКС | `geometry.py`, `targets.py` |
| Ограничения таблицы 2 | запреты с отступом по Ду, спецпроходы одним прямым участком с полями вдоль трассы, угол ≥ 45,5°, техузлы, Kспец при наложениях, ремонт «следования вдоль» | `field.py`, `special.py` |
| Стоимость и показатель | по выгружаемой геометрии; тождества сводки сходятся до копейки | `costing.py` |
| Варианты | три порядка обработки точек + повторная вставка; ранжирование по S | `solve.py`, `improve.py` |
| Выход | GeoJSON по §7 приложения: участки, камеры, техузлы, сводка; концы у входных объектов — побитовые копии координат | `output.py` |
| Режим с глубиной | профиль над/под газом, кабелем, существующей сетью; уклон ≤ 0,10; техузлы в изломах; Kгл | `depth.py` |
| Неподключённые точки | штраф, причина, частичный результат | `tree.py`, `costing.py` |

Результат на конкурсном наборе: три варианта, S = 12,86 / 12,90 / 13,42, все
17 точек подключены, ~1,8 км новой сети, ~270 млн ₽, ~30 с на три варианта
(в тщательном режиме — ~75 с, S = 12,83). Независимый валидатор: 0 ошибок
по всем вариантам.

**Проверка.** 352 теста Python и 5 Java (пример из §7.3 приложения сходится: 0,6913).
Независимый валидатор выхода (`app/case_validator/`, написан отдельно по
тексту приложения) — 0 ошибок на конкурсном наборе и на всех восьми
синтетических сценариях (дороги, трамвай, газ, кабели, парки, недостижимая
точка, район ×4 с 68 точками, id строками и расход строкой «24,87»).

Сводный прогон `backend/verify_all.py` (солвер + валидатор, лучший из трёх
порядков с перестройкой веток):

| Набор | Подключено | S | Ошибок | Предупр. | Сек |
|---|---|---|---|---|---|
| конкурсный | 17/17 | 12,86 | 0 | 3 | 58 |
| big (район ×4, 68 точек) | 68/68 | 50,31 | 0 | 13 | 170 |
| blocks (парк, соцобъект, запрет) | 17/17 | 12,95 | 0 | 3 | 31 |
| mixed (дороги + газ + кабели + трамвай) | 17/17 | 12,95 | 0 | 2 | 114 |
| roads | 17/17 | 12,95 | 0 | 4 | 32 |
| strings (id строками, расход «24,87») | 17/17 | 12,79 | 0 | 4 | 32 |
| tram | 17/17 | 12,90 | 0 | 3 | 32 |
| unreachable (точка в кольце запрета) | 16/17 | 15,33 | 0 | 6 | 28 |
| utilities (газ, кабели) | 17/17 | 12,90 | 0 | 3 | 83 |

До локального поиска было 12,94 / 51,59 / 12,97 / 13,11 / 13,01 / 12,86 /
13,07 / 15,47 / 12,98 — выигрыш от 0,1 до 2,5 %; время (три порядка +
валидатор) после кеширования растров веток и весов не выросло.
Предупреждения — отступления от ближайшей границы ОКС там, где растр 1 м не
видит коридор уже 3 м, и «ступеньки» из двух поворотов; ошибок правил нет.

**Документация.** Правила и трактовки неоднозначностей — `07-case-model.md`;
алгоритм, обработка точек без маршрута, выход, границы — `08-case-algorithm.md`;
целевая архитектура по ТЗ — `02-architecture.md` §0.

## 2. Риски

| Риск | Почему | Что делаем |
|---|---|---|
| Проверяющие трактуют неоднозначности приложения иначе | §9 спецификации: Ду камеры на существующем участке, «ближайшая граница» ОКС, ±2 м у газа короче отступа, дырки полигонов | Трактовки переключаются конфигом без правки кода; независимый валидатор считает оба чтения там, где они расходятся |
| Стек по ТЗ §3.2 (Java 11 / Spring Boot 2.6.3 / PostgreSQL / docker-compose) | Расчётное ядро на Python | Гибрид: Java-приложение (API, загрузка, БД, Swagger, compose) + Python-сервис расчёта; контракт `solve-file` / `inspect-file` / `validate-file` работает, приложение собрано и проверено; compose написан, но без Docker не прогонялся |
| Проверочный набор больше и сложнее конкурсного | «выгружен из рабочих систем», другие типы ограничений, MultiLineString, точки на границе | Синтетические сценарии (roads, utilities, tram, blocks, mixed, strings, big, unreachable); шаг сетки растёт автоматически при > 12 млн ячеек; точки «на стене» до 0,5 м считаются своими |
| Жадное дерево не оптимально | порядок точек задаёт дерево | Три порядка + повторная вставка дали −0,5 % S; при необходимости — больше перестановок (`effort=thorough`) |
| Время расчёта на большом наборе | ~1 с на точку на ядро | Окно волны 1,6 расстояния до сети; растеризация веток в окне; при необходимости — параллельные варианты |
| Округление координат при перепроецировании | углы ровно 90°, T ровно на границе зоны | Запасы: 89,9°, 45,5°, 9,99 м, +1,5 м; длина считается по выгруженным координатам |
