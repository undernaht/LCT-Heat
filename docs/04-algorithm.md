# 04. Алгоритм: поле стоимости, волна, гидравлика

## 1. Пайплайн целиком

```
  1. AOI            bbox вокруг здания и ближайшей сети, шаг сетки
  2. Нагрузка       Q по геометрии здания                       → §2
  3. Предв. Ду      по Q и целевым удельным потерям             → §3
  4. Поле стоимости растеризация слоёв с буферами по Ду         → §4
  5. Волна          Дейкстра ОТ ЗДАНИЯ по всему полю            → §5
  6. Точка врезки   argmin(стоимость[ячейка] + врезка + рек-я)  → §5.2
  7. Трасса         traceback → спрямление → ортогонализация    → §6
  8. Гидравлика     проверка на фактической длине               → §3.3
  9. Итерация       если Ду вырос — шаги 4–8 повторно (обычно не нужно, §7)
 10. Нормоконтроль  по векторной трассе                         → §8
 11. Верт. трасс-ка продольный профиль, глубины, объём выемки   → §8.5
 12. Смета и риски                                              → §9
 13. Альтернативы   другой профиль / диверсификация → к шагу 4   → §10
```

Шаги 4–8 — один «решатель» на профиль. Шаги 1–3 общие для всех профилей.

## 2. Тепловая нагрузка здания

Нужна, чтобы «оживить» весь загруженный район, а не вбивать нагрузки руками.
Считаем по укрупнённым удельным показателям — этого достаточно для выбора диаметра.

**Общая площадь по геометрии:**

```
S_общ = area(контур) × этажность × k_полезной        k_полезной ≈ 0,85
```

**Отопление и вентиляция:**

```
P_от [Вт] = q_уд [Вт/м²] × S_общ × (t_вн − t_нр) / (t_вн − t_нр_баз)
Q_от [Гкал/ч] = P_от × 0,86 × 10⁻⁶
```

Для Москвы `t_нр = −25 °C` (СП 131.13330, параметры Б), `t_вн = 20 °C`.
`q_уд` — из `config/loads.yaml`, по назначению и этажности:

| Тип застройки | q_уд, Вт/м² |
|---|---|
| Жилое, малоэтажное (1–3 эт.) | 95–120 |
| Жилое, средней этажности (4–9 эт.), старый фонд | 75–90 |
| Жилое, современное (после 2000) | 50–65 |
| Общественное, административное | 80–110 |
| Промышленное | по проекту, вводится вручную |

**Горячее водоснабжение:**

```
N [чел] = S_жилая / норма_обеспеченности        (≈ 30 м²/чел)
Q_гвс.ср [Гкал/ч] = a × N × (55 − t_хв) × 10⁻⁶ / 24
Q_гвс.макс = Q_гвс.ср × k_час                    k_час ≈ 2,4
```

`a ≈ 105 л/(чел·сут)`, `t_хв = 5 °C` зимой.

**Итог:** `Q = Q_от + Q_вент + Q_гвс.макс`.

Все коэффициенты — в конфиге, в UI редактируются. Автооценка — это стартовое
приближение; если у пользователя есть проектная нагрузка, он вводит её и
перекрывает расчёт.

## 3. Гидравлика

### 3.1. Расход и параметры потока

```
G [т/ч]  = 1000 × Q [Гкал/ч] / Δt [°C]
v [м/с]  = (G × 1000/3600) / (ρ × A)         ρ ≈ 960 кг/м³,  A = πd²/4
λ        = 0,11 × (kэ / d)^0,25              kэ = 0,0005 м   (СП 124.13330, п. 8.5)
R [Па/м] = λ × ρ × v² / (2d)
```

`Δt` берётся из температурного графика точки врезки: 150/70 → 80, 130/70 → 60,
95/70 → 25.

### 3.2. Подбор диаметра

Ряд Ду: 32, 40, 50, 65, 80, 100, 125, 150, 200, 250, 300, 350, 400, 500.
Наименьший внутренний диаметр в тепловых сетях — 32 мм (п. 8.7).
Диаметры подающего и обратного принимаем одинаковыми (п. 8.6).

Перебираем ряд снизу вверх, берём первый Ду, для которого одновременно:

```
R ≤ R_доп        (30–80 Па/м для распределительных сетей, до 100 для ответвлений)
v ≤ v_доп        (≤ 3,5 м/с)
```

> **Практическое наблюдение.** Для подключения отдельного здания ограничение по
> скорости почти никогда не активно — диаметр определяют удельные потери.
> Скорость становится критерием только на магистралях.

### 3.3. Проверка на фактической длине

После построения трассы:

```
ΔP [Па] = R × L × (1 + α) × 2          α ≈ 0,3 — доля местных сопротивлений
                                       ×2 — подающий + обратный
H [м вод. ст.] = ΔP / (ρ × g)
```

Проверки:

1. `H ≤ H_располагаемый` в точке врезки — иначе Ду вверх либо другая точка;
2. `Q ≤ резерв пропускной способности` участка;
3. `Q ≤ резерв мощности источника`.

Если (2) или (3) не выполняются — точка врезки либо отбрасывается, либо помечается
как «требует реконструкции» с оценкой стоимости перекладки участка на следующий Ду
(см. §5.2).

### 3.4. Сквозной пример

Используется в демо и в тестах как эталон.

Перспективное 9-этажное жилое здание нового строительства, контур 900 м²,
S_общ = 6 885 м², q_уд = 58 Вт/м²:

| Величина | Значение |
|---|---|
| Отопление | 0,343 Гкал/ч |
| ГВС (максимальный час) | 0,120 Гкал/ч |
| **Расчётная нагрузка Q** | **0,464 Гкал/ч** |
| График | 130/70 (Δt = 60) |
| Расход G | 7,73 т/ч |
| Подобранный Ду | **80 мм** |
| Скорость v | 0,45 м/с |
| Удельные потери R | 37 Па/м |
| Длина трассы L | 214 м |
| Потери напора ΔP | 0,20 бар (2,2 м вод. ст.) |
| Отклонён Ду65 | R = 109 Па/м при допустимых 100 |

Пример иллюстрирует §3.2: Ду65 отклонён по удельным потерям, при этом скорость на
нём 0,67 м/с — вчетверо ниже предела. Ограничение по скорости неактивно.

> Пример зафиксирован в тестах (`tests/test_loads.py`,
> `test_reference_end_to_end_geometry_to_diameter`): цепочка «геометрия → нагрузка →
> расход → диаметр → потери напора» считается кодом, а не переписана в документ
> руками. Рассинхронизация документа и кода ломает сборку.

## 4. Поле стоимости

Растр с шагом 1 м (2 м для больших областей). Значение ячейки — **стоимость
прокладки одного метра трассы в этой точке, в рублях**.

```
cost[y, x] = pipe(Ду, способ)                  постоянна вдоль трассы
           + earthwork(Ду) × surface_mult[y,x]  зависит от покрытия
           + penalty[y, x]                      надбавки зон
```

Модель **аддитивная, а не мультипликативная**. Покрытие удорожает земляные работы
и восстановление, но не стоимость самой трубы: множитель на всю сумму завышал бы
цену трубы под асфальтом. Побочная выгода — значения в поле сразу в рублях, их
может проверить сметчик, а не только автор алгоритма.

`MCP_Geometric` считает стоимость перехода как среднее стоимостей двух ячеек,
умноженное на геометрическое расстояние (1 или √2) — то есть массив должен
содержать именно **стоимость на метр**, а не на ячейку. При шаге сетки, отличном
от 1 м, стоимость домножается на шаг.

### 4.1. Слои

Слои контекста, влияющие на трассу:

| Слой | Источник | Как влияет |
|---|---|---|
| Здания | OSM | запрет: контур + нормативный буфер по Ду, способу, грунту |
| Водные объекты | OSM | запрет |
| Улицы | OSM | класс покрытия, полоса 1,5 м от бортового камня, закрытый переход |
| Железные дороги | OSM | полоса отвода, ГНБ при пересечении |
| Землепользование | OSM `landuse`, `leisure` | класс покрытия: парки и газоны дешевле грунта |
| Деревья и кустарники | OSM `natural=tree`, `tree_row` | надбавка в зоне 2,0 / 1,0 м; снос со стоимостью озеленения |
| Чужие сети | шесть классов | полоса нормативного отступа с учётом давления газа и напряжения кабеля |
| Существующие теплосети | — | техкоридор шириной 5 м со скидкой 0,85 |
| Земельные участки, ЗОУИТ | — | надбавка «стоимость согласований» |

> **Растр консервативен примерно на ячейку.** Растеризация с `all_touched`
> расширяет любую зону до целой ячейки, поэтому при шаге 1 м эффективный отступ
> на полметра-метр больше нормативного. Это осознанный запас: поиск держится
> дальше от препятствий, а точные расстояния всё равно меряет нормоконтроль по
> вектору. Зафиксировано тестом `test_raster_zones_are_conservative_by_one_cell`.

Множители земляных работ (`surface_multiplier` в `costs.yaml`):

| Покрытие | Множитель |
|---|---|
| Грунт, пустырь | 1,0 |
| Газон | 1,1 |
| Тротуар, плитка | 1,6 |
| Дворовый проезд | 2,0 |
| Улица местного значения | 3,0 |
| Магистральная улица | 4,5 |
| Существующий техкоридор | 0,85 |

Надбавки зон, ₽/м (`zone_penalty_per_m`) — **веса поиска, не сметные расценки**,
см. §9.1:

| Зона | Надбавка |
|---|---|
| Полоса нормативного отступа от чужой сети | 250 000 |
| Проезжая часть (только прокол / ГНБ) | 80 000 |
| Полоса отвода ж/д (только ГНБ в футляре) | 150 000 |
| Чужой участок в частной собственности | 35 000 |
| ЗОУИТ с ограничениями | 60 000 |

Непроходимо (`np.inf`): контуры зданий с нормативным буфером, водные объекты,
ЗОУИТ с прямым запретом прокладки.

### 4.2. Буферы вокруг зданий зависят от Ду и способа прокладки

Из СП 124.13330, табл. А.3 (см. [`90-normatives.md`](90-normatives.md)):

| Способ | Ду < 500 | 500–800 | ≥ 800 |
|---|---|---|---|
| Канальная (от стенки канала) | 2,0 м | 5,0 м | 8,0 м |
| Бесканальная (от оболочки) | 5,0 м | 7,0 м | ≥ 9,0 м |

Для подключения отдельного здания Ду почти всегда < 500, поэтому буфер определяется
**только способом прокладки**: 2,0 м против 5,0 м. Разница принципиальная — в
плотной застройке бесканальная прокладка часто просто не проходит между домами,
и алгоритм сам выбирает канальную, потому что она «дешевле» с учётом обхода.

### 4.3. Пересечение чужих сетей — ключевой приём

Наивный подход — построить буфер 1,5 м вокруг водопровода и запретить его. Тогда
трасса **не сможет пересечь водопровод вообще**, а по нормативам пересекать можно:
СП требует лишь разнести сети по вертикали на 0,2 м (табл. А.1).

Решение: полоса нормативного отступа получает не бесконечную, а **высокую конечную
надбавку**. Скалярное поле стоимости само разделяет два случая, потому что
стоимость накапливается по длине. Для Ду80 базовая стоимость в грунте —
18 000 + 9 000 = 27 000 ₽/м, надбавка полосы — 250 000 ₽/м:

```
пересечь поперёк:  3 м × 277 000  =   0,8 млн ₽   ≈ обход в 30 м → приемлемо
идти вдоль 200 м:  200 м × 277 000 =  55   млн ₽   → никогда
```

То есть **пересечение остаётся возможным, а параллельное следование становится
запретительно дорогим — без всякой направленной анизотропии**. Правило выбора
надбавки: `надбавка × ширина полосы` должно быть сопоставимо со стоимостью
типичного обхода (десятки метров базовой прокладки), а `надбавка × 20 м` —
заведомо дороже любой альтернативы.

Тот же приём работает для дорог. Пересечь магистральную улицу шириной 25 м:
25 × (27 000 + 80 000) ≈ 2,7 млн ₽ — правдоподобная цена ГНБ такой длины. Идти
вдоль неё 300 м по проезжей части — 32 млн ₽, чего не выберет ни один профиль.

Тот факт, что все три числа выражены в рублях и проверяемы отраслевым
специалистом, — не косметика: он превращает «настройку весов алгоритма» в
обсуждение сметы, а это разговор, который согласующая сторона умеет вести.

Окончательная проверка допустимости пересечения (0,2 м по вертикали, угол,
метод производства работ) выполняется в нормоконтроле по вектору (§8), где видна
геометрия каждого пересечения. Растр отвечает только за поиск.

## 5. Волна и выбор точки подключения

### 5.1. Одна волна от здания

Дейкстра (`skimage.graph.MCP_Geometric`) запускается **от точки ввода в здание**
и заполняет всё поле: `cost_to_building[y, x]` — минимальная стоимость прокладки
от этой ячейки до здания.

Почему от здания, а не от сети: поле стоимости изотропно, поэтому стоимость пути
в обе стороны одинакова. Одна волна даёт стоимость до **всех** точек существующей
сети сразу — включая врезку в середину любого участка, а не только в существующие
камеры.

Альтернатива — мультистарт от всех кандидатов врезки — даёт то же самое, но
**не позволяет учесть индивидуальную стоимость каждого кандидата**: у мультистарта
все источники стартуют с нулевой стоимостью. А стоимость врезки и реконструкции
у разных участков разная, и часто именно она определяет ответ.

### 5.2. Выбор кандидата

Кандидаты — все ячейки растра, покрытые существующими теплосетями и прошедшие
гидравлический фильтр (§3.3). Для каждой:

```
total(i) = cost_to_building[i]
         + врезка(Ду_участка)              устройство узла врезки, камеры
         + реконструкция(участок, Q)       0, если резерва хватает
         + подключение_к_источнику(Q)      0, если резерва источника хватает
```

Берём минимум. `traceback(i*)` даёт трассу.

Такая формулировка честно сравнивает «дальняя точка с дешёвой врезкой» и
«ближняя, но требующая перекладки участка Ду80 → Ду125». Обе величины в рублях,
складываются напрямую.

**Побочный результат, ценный для UI:** мы получаем `total` по *всем* кандидатам, а
не только по лучшему. Отсюда — фраза «рассмотрено 14 точек врезки, выбрана ТК-118»
с таблицей отставания остальных. Это бесплатная объяснимость.

## 6. Из растрового пути в проектную трассу

Путь по сетке — «лесенка», инженерно непригоден. Три шага.

### 6.1. Спрямление

Жадное удаление вершин: для каждой тройки идущих подряд вершин пробуем заменить
её прямым отрезком. Принимаем, если

- отрезок не задевает непроходимые ячейки;
- интеграл стоимости вдоль отрезка ≤ стоимости исходного участка × (1 + ε),
  ε ≈ 0,02.

Повторяем до стабилизации. Убирает и дискретизационный шум, и угловую ошибку
8-связности (до 22,5°), ради которой иначе пришлось бы городить 16-связность.

### 6.2. Ортогонализация

Проектные трассы идут параллельно застройке: так их проще строить, согласовывать
и обслуживать. Направление сетки кварталов берётся из азимутов ближайших улиц,
взвешенных по длине и усреднённых по модулю 45° — сетка симметрична, «север-юг»
и «запад-восток» для нас одно семейство. Усреднение идёт через единичный вектор
учетверённого угла, иначе 1° и 44° дали бы бессмысленное среднее 22°.

Каждый участок разворачивается к ближайшему направлению `база + k·45°`, вершины
пересчитываются как пересечения соседних прямых, концы закреплены — точка ввода
и точка врезки двигаться не могут.

Три вещи, без которых это не работает, и все три выяснились на замерах:

1. **Локальный откат вместо отказа целиком.** Одна вершина, уехавшая в буфер
   соседнего дома, обнуляла выравнивание всей трассы: стоимость становилась
   бесконечной, результат отбрасывался. Теперь откатывается только виновная
   вершина. Две трассы из трёх до этого не выравнивались вообще.
2. **Убывающий допуск.** Пробуются 22°, 14°, 8°: если смелый разворот увёл
   трассу в запрет или удорожил её больше чем на 6 %, пробуется щадящий.
3. **Несколько проходов.** За один проход не сходится: откат вершины меняет
   соседние прямые, и следующий проход выравнивает то, что пришлось оставить.
   На `kvartal_1` второй проход поднял выравнивание с 17 % до 35 % длины.

**Замер.** Доля длины, идущей строго по сетке кварталов: `persp_2` — 80 %,
`kvartal_1` — 36 %, `persp_1` — 10 %. Последняя трасса пересекает железную дорогу
по диагонали, и выровнять её без обхода дороже 6 % невозможно. Это правильный
ответ: диагональные трассы в жизни тоже бывают, и заставлять их идти лесенкой
ради красоты — удорожать стройку.

### 6.3. Расстановка узлов

Углы поворота, компенсаторы и камеры по нормативным интервалам — влияет на смету
и на реалистичность картинки.

## 7. Итерация по диаметру

Формально расчёт циклический: буфер зависит от Ду → трасса → длина → проверка
напора → возможно другой Ду → другой буфер.

На практике цикл почти всегда сходится за один проход, потому что пороги буферов
проходят по Ду 500 и 800, а подключение отдельного здания — это Ду 50–150.
Диаметр может вырасти на шаг из-за длины, но буфер при этом не изменится, а значит
не изменится и трасса — достаточно пересчитать гидравлику и смету.

Полный пересчёт запускаем, только если Ду перешёл порог 500 или сменился способ
прокладки. Ограничение — 3 итерации, дальше фиксируем и сообщаем.

## 8. Нормоконтроль — по вектору, не по растру

Растр отвечал за поиск. Проверка идёт по итоговой векторной трассе — иначе мы
проверяли бы собственную дискретизацию.

### 8.1. Как отличить следование от пересечения

Наивный критерий «трасса пересекает геометрию объекта» не работает. Подход к
переходу через улицу неизбежно проходит вплотную к бортовому камню, а трасса при
этом проезжую часть ещё не пересекла — посегментная проверка объявляла бы
нарушением каждый переход. То же с чужими сетями: у самого пересечения трасса
несколько метров идёт внутри нормативного коридора.

Правильный критерий — **длина участка вхождения трассы в нормативный коридор**:

```
коридор = объект.buffer(норматив)
для каждого куска (трасса ∩ коридор):
    кусок длиннее порога  → следование вдоль → правило по горизонтали (табл. А.3)
    кусок короче порога   → пересечение      → правило по вертикали  (табл. А.1)
```

**Порог обязан масштабироваться от норматива.** Перпендикулярное пересечение
коридора шириной `2 × норматив` даёт кусок ровно такой длины, под углом — длиннее.
При отступе 4,0 м от оси железной дороги коридор 8 м, и фиксированный порог 8 м
объявлял бы каждое пересечение ж/д следованием вдоль неё — что и произошло на
первом прогоне. Поэтому `порог = max(8 м, 3 × норматив)`.

### 8.2. Конфликт по вертикали — это стоимость, а не запрет

Кабели связи и силовые лежат на глубине 0,8–0,9 м, а канальная прокладка Ду80
занимает 0,50–1,18 м от поверхности. То есть **в точке пересечения конструкции
пересекаются буквально**, и формальная проверка даёт просвет 0,00 м при
нормативе 0,50 м.

В проекте это решают не переносом трассы, а местным заглублением или футляром.
Поэтому такой конфликт — `conditional` с расчётом требуемого заглубления:

> ⚠️ 403–407 м · До силовых кабелей до 35 кВ · норма 0,50 · факт 0,00
> └ требуется местное заглубление на 0,97 м (проход ниже)

Рассматриваются оба варианта — пройти ниже и пройти выше, — берётся меньшее
перемещение; проход выше отбрасывается, если верх конструкции оказывается выше
минимального заглубления. `fail` остаётся только когда требуемое заглубление
превышает 2,5 м. Окно, в котором это случается, узкое, и не случайно: просвет
меньше нормы возможен, лишь пока чужая сеть близко к нашей конструкции, а это
ограничивает требуемое заглубление величиной `высота конструкции + 2 × норматив`.
Для Ду80 это 1,68 м — то есть **пересечения обычных сетей разрешимы всегда**,
и это правильный ответ, а не поблажка.

### 8.3. Что попадает в протокол

Все нарушения плюс **самая тугая из проходящих проверок по каждому правилу**.
Иначе протокол на реальном районе — это сотни строк «до дома 40 м при норме 2 м»,
в которых теряется единственное, что важно согласующему инженеру.

Пример с района `small`, трасса 537 м:

| Участок | Правило | Норматив | Факт | Статус | Пункт |
|---|---|---|---|---|---|
| 403–407 м | До силовых кабелей до 35 кВ (пересечение) | 0,50 м | 0,00 м | ⚠️ | табл. А.1 |
| 451–455 м | То же | 0,50 м | 0,00 м | ⚠️ | табл. А.1 |
| 414 м | До фундаментов зданий (канальная, Ду < 500) | 2,00 м | 2,84 м | ✅ | табл. А.3 |

Статусов три:

- `pass` — норматив выдержан;
- `conditional` — можно, но нужны мероприятия, и это стоит денег. СП допускает
  уменьшение расстояний в стеснённых условиях при защитных мероприятиях
  (Приложение Д), поэтому отступление не ниже половины норматива — не отказ;
- `fail` — норматив нарушен и защитными мероприятиями не закрывается.

**Вариант со статусом `fail` не попадает на Парето-фронт.** Недопустимая трасса —
не компромисс, а брак, и предлагать её как «зато дешевле» нельзя.

## 8.5. Вертикальная трассировка: продольный профиль

План трассы отвечает на вопрос «где», профиль — «на какой глубине». Это не
украшение: **объём земляных работ, то есть примерно половина сметы, определяется
профилем, а не длиной**. Две трассы одинаковой длины по одному и тому же
покрытию стоят по-разному, если одна идёт по ровному месту, а вторая по балке.

Реализация — `app/routing/profile.py`, рельеф — `app/geo/elevation.py`.

### 8.5.1. Источник высот

DEM берётся из AWS Terrain Tiles (открытые, без ключа), кодировка `terrarium`:

```
h = R · 256 + G + B / 256 − 32768
```

Скрипт `data/fetch_dem.py` скачивает тайлы на bbox района, склеивает и пишет
`elevation.tif` рядом с остальными слоями. Для района `small` это ~5 м/пиксель,
отметки 119–182 м, файл 272 КБ.

**Рельеф необязателен.** Нет `elevation.tif` — `Terrain.available == False`,
профиль помечается недоступным, всё остальное считается как раньше. Молчаливой
подстановки «плоской земли» нет: это выглядело бы как выполненный расчёт.

### 8.5.2. Рельеф в поле стоимости

До профиля рельеф участвует ещё в горизонтальном поиске (§4). Уклон местности
считается по градиенту DEM на той же сетке, что и поле стоимости:

```
surface_mult(x,y) ← surface_mult(x,y) · (1 + k · slope(x,y)),   k = 2,5
blocked(x,y)      ← blocked(x,y) ∨ (slope(x,y) > 0,45)
```

Копать на склоне дороже (крепление стенок, вывоз грунта, техника), а склон
круче 0,45 для траншейной прокладки непригоден. Поэтому трасса сама предпочтёт
обойти овраг, а не спускаться в него.

### 8.5.3. Проектирование отметок трубы

Требование СП 124.13330: уклон не менее **0,002** в сторону спускных устройств.
Земля почти нигде не имеет нужного уклона в нужную сторону, поэтому труба
кладётся с переменной глубиной.

Алгоритм:

1. **Дискретизация.** Отметки земли снимаются вдоль трассы с шагом 5 м
   (мельче бессмысленно — DEM грубее).
2. **Разбиение на участки одного направления.** Профиль земли сглаживается
   скользящим средним и делится по точкам смены знака уклона. Сглаживание
   обязательно: DEM шумит на метр, и без него каждый пиксель становился бы
   перегибом, а труба — пилой.
3. **Прямая на каждом участке.** Направление уклона берётся по земле, величина —
   `max(|уклон земли|, 0,002)`. Прямая поднимается настолько высоко, насколько
   позволяет минимальное заглубление во **всех** точках участка:

   ```
   i = min over segment (z_земли − h_min − slope · (d − d₀))
   z_трубы(d) = i + slope · (d − d₀)
   ```

   Так выемка получается наименьшей из допустимых.
4. **Страховка.** Финальный `min(z_трубы, z_земли − h_min)` гарантирует, что
   минимальное заглубление не нарушено нигде, даже если сглаживание ошиблось.

### 8.5.4. Арматура и объём выемки

Локальные максимумы профиля трубы — **воздушники**, минимумы — **спускники**
(ближе 25 м друг к другу не ставим). Объём выемки — интеграл по трассе:

```
V = ∫ (глубина(d) + h_конструкции) · b_траншеи(d) dd
b = 2·Ду + 0,30 (между трубами) + 2 · 0,35 (на стенки)
```

### 8.5.5. Пьезометрические проверки

В двухтрубной замкнутой системе геодезический перепад **не влияет** на
располагаемый напор у потребителя — подача и обратка компенсируют друг друга.
Зато он определяет абсолютное давление, и здесь две границы:

| Проверка | Условие | Что означает нарушение |
|---|---|---|
| Невскипание в верхней точке | `H_ст − z_max ≥ h_вск(t_подачи)` | вверху сеть вскипит |
| Давление в нижней точке | `H_ст − z_min ≤ 163 м` | внизу давление выше допустимого для оборудования |
| Максимальная глубина | `depth_max ≤ 4,0 м` | нужно водопонижение и крепление стенок |

`h_вск` зависит от температуры подачи: 38 м при 150 °C, 17 м при 130 °C, 3 м при
95 °C. Статический уровень `H_ст` — свойство сети (задаётся подпиточным насосом
источника), читается из атрибута `static_head_m` узла-источника. **Нет его в
исходных данных — проверки не выполняются**, вместо того чтобы подставить
правдоподобное число.

В генераторе `H_ст` не выдумывается, а выводится из норматива: верхняя отметка
сети + требование невскипания + 8 м запаса на будущие подключения. Для района
`small`: 156,9 + 17 + 8 = 181,9 м.

### 8.5.6. Что даёт профиль смете

Базовая ставка земляных работ (`earthwork_per_m`) считает траншею **минимальной**
глубины. Всё, что глубже из-за уклона и рельефа, идёт отдельной строкой:

```
V_доп = max(0, V_профиля − (h_min + h_констр) · b · L)
стоимость = V_доп · 2 800 ₽/м³
```

Иначе рельеф был бы посчитан дважды или не посчитан вовсе. На районе `small`
это 2,9–7,2 % сметы в зависимости от трассы.

Профиль строится одинаково в трёх местах: одиночный расчёт, ручная правка и
групповое подключение (там — по каждому участку своим диаметром, участки не
перекрываются). Единая точка входа — `profile.for_route(area, line, …)`.
Без этого ручная правка выглядела бы систематически выгоднее расчётной трассы.

### 8.5.7. Замеры на районе `small`

| Трасса | Длина | Отметки земли | Глубина | Выемка | Воздушн./спускн. | Доплата |
|---|---|---|---|---|---|---|
| `persp_1` | 439 м | 150,0–159,3 м | 0,50–3,40 м | 1084 м³ | 3 / 1 | 1,35 млн ₽ |
| `persp_2` | 430 м | 145,6–149,5 м | 0,50–1,73 м | 826 м³ | 2 / 3 | 0,67 млн ₽ |

## 9. Смета и риски

### 9.1. Веса поиска ≠ сметные расценки

Это выяснилось при первом прогоне на реальном районе и стоит отдельного пункта.

Надбавка 250 000 ₽/м на полосу отступа от чужой сети подобрана под **поведение
алгоритма** (§4.3), а не под стоимость работ. При интегрировании поля вдоль
найденной трассы она дала 8,9 млн ₽ «пересечений» на 456 м — то есть около
890 тыс ₽ за каждое пересечение водопровода, что завышено втрое-впятеро.
Смета получилась 32,6 млн вместо 24,7 млн.

Причина фундаментальная: чтобы запретить следование вдоль чужой сети, надбавка
обязана быть заведомо выше реальной цены пересечения. Иначе трассировщик,
сэкономив на обходе, пойдёт вдоль коридора — а это уже нарушение норматива.
То есть завышение здесь **делает алгоритмическую работу**, и убрать его нельзя.

Поэтому две величины разведены:

| | Веса поиска | Смета |
|---|---|---|
| Где живут | `zone_penalty_per_m` | `crossing_setup`, `crossing_per_m` |
| Как считаются | интеграл по растру | поштучно по векторной трассе |
| Что описывают | «сюда лучше не ходить» | стоимость устройства перехода |
| Входят в итог | нет | да |

Смета берёт из поля только трубу и земляные работы (интеграл минус надбавки),
а пересечения считает по фактической геометрии: сколько чужих сетей реально
пересечено, какой длины закрытый переход под улицей, есть ли ж/д. Итог —
величина, которую может проверить сметчик, а не артефакт настройки весов.

Страховка от того, что трассировщик всё-таки пойдёт вдоль коридора, — не
стоимость, а **нормоконтроль по вектору** (§8): следование ближе норматива он
поймает независимо от того, во сколько его оценило поле.

### 9.2. Статьи сметы

| Статья | Формула |
|---|---|
| Труба и монтаж | `ставка(Ду, способ) × L` |
| Земляные работы и восстановление | `Σ по покрытиям: ставка(покрытие) × L_i` |
| Пересечения | `Σ по фактическим пересечениям: setup + ставка/м × длина` |
| Камеры и узлы | `число × ставка(Ду)` |
| Врезка | `ставка(Ду_существующего)` |
| Реконструкция | если требуется по §3.3 |
| Тепловые потери за срок службы | дисконтированный OPEX |

### 9.3. Пересечения считаются по фактическому пересечению, а не по заходу в зону

Два уточнения, оба всплыли на реальном районе и оба завышали смету.

**Параллельные пути — один переход.** Двухпутная железная дорога и улица с
разделительной полосой приходят из OSM несколькими линиями. Считать по каждой
отдельный ГНБ с отдельной мобилизацией нельзя: в жизни это один прокол под всем
полотном. Пересечения одного типа, отстоящие вдоль трассы меньше чем на 30 м,
объединяются в одно.

**Заход в полосу отвода — ещё не пересечение.** Полоса отвода ж/д шире самих
путей (20 м против нескольких), и трасса может задеть её угол, не пересекая
рельсы. На `persp_1` такой заход длиной 1,4 м давал полную мобилизацию ГНБ —
984 тыс ₽ на ровном месте. Закрытый переход начисляется, только если трасса
реально пересекает ось пути; заход в полосу отвода без этого — вопрос
нормативного отступа, и им занимается нормоконтроль, а не смета.

Замер на районе `small`, трасса 450 м, Ду80: **23,7 млн ₽ ≈ 53 тыс ₽/м** —
прокладка 16,2 млн, ГНБ под ж/д 2,1 млн, камеры 2,6 млн, тепловые потери за
25 лет 2,1 млн, врезка 0,76 млн.

### 9.4. Плата за подключение ≠ смета работ

Это разные величины, и путать их нельзя. Смета — стоимость строительно-монтажных
работ. **Плата за подключение** — тариф, утверждённый органом регулирования, и
считается она по ФЗ-190 ст. 14 и ПП РФ № 787:

| Подключаемая нагрузка | Как определяется плата |
|---|---|
| ≤ 0,1 Гкал/ч | Фиксированная — 550 ₽ с НДС (ФЗ-190 ст. 14) |
| 0,1 … 1,5 Гкал/ч | Двухставочная: ставка за нагрузку + ставка за протяжённость по Ду и типу прокладки |
| > 1,5 Гкал/ч | По индивидуальному проекту, расчёт по ставкам неприменим |

Вот здесь и замыкается вся история: **ставка за протяжённость зависит от длины
трассы по диаметрам**, то есть оптимизатор минимизирует ровно ту сумму, которую
платит застройщик. На `persp_1` (0,464 Гкал/ч, 450 м, Ду80) плата выходит
17,7 млн ₽ с НДС, из которых 13,6 млн — именно составляющая за протяжённость.
Сократить трассу на 50 м — минус полтора миллиона в квитанции заявителя.

> ⚠️ Ставки в `costs.yaml` ориентировочные. Действующие утверждает региональный
> регулятор отдельным приказом на год; перед защитой подставить приказ по Москве.
> Флаг `calibrated: false` протаскивается в PDF и в UI, чтобы цифру не приняли
> за официальную.

**Риск согласований** — отдельная ось, не в рублях:

```
risk = w1 × число_чужих_участков
     + w2 × длина_вскрытия_проезжей_части
     + w3 × число_пересечений_ЗОУИТ
     + w4 × число_закрытых_переходов
```

Она идёт в Парето-фронт наравне со стоимостью. Вариант «дороже на 8 %, но без
вскрытия магистральной улицы» часто и есть правильный ответ — а по одной только
стоимости он проиграет.

## 10. Варианты

Три содержательно разных ответа получаем **разными профилями стоимости**, а не
разными запусками одного алгоритма:

| Профиль | Что меняется в поле | Статус |
|---|---|---|
| `min_cost` | Базовые множители, риск с малым весом | работает |
| `min_approvals` | Чужие участки ×6, проезжая часть ×3, ЗОУИТ ×4, техкоридор ×0,6 | работает |
| `reliable` | Запас пропускной способности ×1,3, предпочтение независимого источника | ⚠️ см. ниже |

> ⚠️ **`reliable` пока не даёт отдельного ответа.** Флаг
> `prefer_independent_source` не реализован, а запас пропускной способности на
> текущем датасете ни на что не влияет: у всех кандидатов резерв (2,2 Гкал/ч)
> многократно перекрывает потребность (0,46 Гкал/ч). Профиль строит ту же
> трассу, что `min_cost`, и корректно отсеивается дедупликацией. Чтобы он стал
> содержательным, нужен либо второй источник в датасете, либо загруженная сеть.

Дополнительно — **диверсификация**: после найденной трассы умножаем стоимость в
коридоре шириной 30 м вокруг неё на 3 и ищем снова. Так получаются действительно
непохожие альтернативы, а не три параллельные линии в метре друг от друга.

Итог — до 5 вариантов, из них показываем недоминируемые по {стоимость, риск,
тепловые потери} плюс лучший по каждой оси. Похожие трассы схлопываются:
если расстояние Хаусдорфа между вариантами меньше 25 м, это одна и та же трасса,
а не альтернатива.

Замер на `persp_1`: 4 варианта за 2,7 с, на Парето-фронте два — `min_cost`
(456 м, 24,7 млн ₽, риск 10,0) и `min_approvals+1` (733 м, 39,3 млн ₽,
риск 6,5). То есть «на 60 % длиннее и в полтора раза дороже, зато вдвое меньше
риск согласований» — ровно тот выбор, который на практике делает заказчик.

### 10.0. Ручная правка: оптимум не приговор

Автоматический ответ — предложение, а не решение. Инженер знает то, чего нет в
данных: здесь через год снесут павильон, здесь собственник не пустит, а вдоль
забора копать удобнее. Поэтому трассу можно поправить на карте — тянуть вершины,
вставлять новые на серединах участков, удалять лишние — и тут же получить те же
числа, что и для расчётной.

**Никаких поблажек ручной трассе.** Считает её тот же код: те же модули
гидравлики, сметы, платы и нормоконтроля. Дополнительно проверяется сама
геометрия, чего для расчётной трассы не требуется:

| Проверка | Зачем |
|---|---|
| Начинается у здания | Отрыв больше 25 м — не промах курсора, а другая трасса |
| Доходит до сети | Конец дальше 15 м от существующего участка — врезки нет |
| Не идёт по запретной зоне | Считается длина участка внутри контуров зданий с буфером и водных объектов |
| Не пересекает саму себя | Труба не может проходить сквозь себя |
| Не выродилась | Короче пяти метров — не трасса |

Концы подтягиваются автоматически: попасть мышью точно в грань здания или в ось
трубы невозможно, а отрыв на метр — промах курсора, а не ошибка проектировщика.
Подтягивание работает только в пределах допуска: тянуть через полрайона нельзя.

**Главное — разница с оптимумом показывается в рублях.** Замер на `persp_1`:

| Правка | Длина | Стоимость | Разница | Вердикт |
|---|---|---|---|---|
| Без правок | 444 м | 22,47 млн ₽ | −0 % | годится |
| Вершина сдвинута на 60 м | 550 м | 28,13 млн ₽ | +25 % | самопересечение |
| Спрямили до прямой | 388 м | 20,26 млн ₽ | **−10 %** | 104 м по запретной зоне |
| Оборвали на середине | 362 м | 18,41 млн ₽ | −18 % | не доходит до сети |

Третья строка — то, ради чего проверка и нужна: «улучшение на глаз» выходит
дешевле на два миллиона и при этом недопустимо. Без нормоконтроля по вектору эта
трасса выглядела бы выигрышем.

Проверка занимает **около секунды** — вдвое-втрое быстрее полного расчёта:
поле стоимости строится один раз, волна Дейкстры не нужна вовсе.

### 10.1. Подключение группы зданий — дерево Штейнера

Для квартала перспективной застройки задача перестаёт быть «трасса от здания до
сети»: нужен общий коридор, от которого расходятся вводы. Точное решение задачи
Штейнера NP-трудно, поэтому используется **жадное инкрементальное наращивание**:

1. здания сортируются по убыванию нагрузки — крупнейший задаёт магистраль;
2. каждое следующее ищет ближайшую точку врезки не только на существующей сети,
   но и **на уже построенных ветках**;
3. врезка в собственную новую сеть дешевле врезки в действующую магистраль:
   не нужно отключать существующих потребителей;
4. после построения дерева нагрузки агрегируются снизу вверх, ветки режутся в
   точках врезки, и каждый участок получает свой диаметр.

Агрегация требует аккуратности с направлением. Ветка идёт от здания (`d = 0`) к
точке врезки (`d = L`), а поток движется навстречу. Значит участок `[d_k, d_k₊₁]`
несёт собственную нагрузку здания плюс нагрузки всех поддеревьев, врезавшихся
**ближе к зданию**, чем `d_k`.

**Замер на районе `small`**, три перспективных здания суммарно 1,44 Гкал/ч:

| | Группой | Раздельно | Экономия |
|---|---|---|---|
| Длина трассы | 1 136 м | 1 692 м | 556 м (33 %) |
| Стоимость СМР | 61,2 млн ₽ | 79,8 млн ₽ | 18,6 млн ₽ (23 %) |
| Плата за подключение | 46,1 млн ₽ | 63,5 млн ₽ | 17,4 млн ₽ |

Дерево: общий коридор Ду100 длиной 416 м на `persp_2` и `persp_3`, от него ввод
Ду80 (11 м) и Ду65 (270 м). `persp_1` подключился к сети самостоятельно — до него
общий коридор не дотянулся, и алгоритм честно это показал, а не притянул.

Экономия по стоимости (23 %) ниже, чем по длине (33 %): общий коридор идёт
большим диаметром, и часть выигрыша съедается более дорогой трубой. Это и есть
содержательный ответ, а не тот, который хотелось бы получить.

> **Грабли.** Первая версия склеивала всё дерево в одну ломаную, чтобы посчитать
> пересечения и нормоконтроль одним вызовом. Ветки расходятся в разные стороны, и
> склейка породила фиктивный отрезок через полрайона: 18 ложных нарушений и смета
> дороже раздельного подключения. Пересечения и нормоконтроль считаются **по
> каждой ветке отдельно** — ветки не перекрываются, поэтому двойного счёта нет.

## 11. Объяснимость — что откуда берётся

Ничего не генерируется моделью: все формулировки навешиваются на уже посчитанные
числа.

| Утверждение в UI | Источник |
|---|---|
| «Рассмотрено 14 точек врезки, выбрана ТК-118» | таблица `total(i)` из §5.2 |
| «62 % стоимости — ГНБ под Ленинским проспектом» | разложение сметы §9 |
| «Трасса ушла во двор: вдоль улицы не выдерживается 1,5 м до бортового камня» | правило, которое дало ∞/высокую стоимость в отвергнутом коридоре |
| «Прямая короче на 90 м, но пересекает 2 участка и требует ГНБ (+3,2 млн ₽)» | расчёт сметы и нормоконтроля для прямой линии «здание → точка врезки» |
| «Ду80: при Ду65 удельные потери 109 Па/м при допустимых 100» | отвергнутые кандидаты из перебора §3.2 |

Приём с «идеальной прямой»: рисуем её пунктиром и прогоняем через тот же
нормоконтроль и ту же смету. Контраст между ней и реальной трассой объясняет
ценность сервиса нагляднее любого текста.

## 12. Известные ограничения метода

Честный список — чтобы не выяснять это на защите.

| Ограничение | Влияние | Как живём |
|---|---|---|
| Шаг сетки 1 м | Погрешность длины ~1 % | Достаточно для оценки платы за подключение |
| 8-связность даёт угловую ошибку до 22,5° | «Лесенка» | Снимается спрямлением (§6.1) |
| Поле стоимости изотропно | Не выражаем «вдоль улицы копать дешевле, чем поперёк» напрямую | Выражаем через геометрию слоёв: тротуар и проезжая часть — разные полигоны |
| Гидравлика стационарная, один расчётный режим | Нет переходных режимов и летнего режима ГВС | Для выбора Ду достаточно |
| Нет грунтовых вод и геологии | Не считаем водопонижение и просадочность | Рельеф учтён (§8.5), геология — переключатель района |
| DEM ~5 м/пиксель, застройка не вычтена | Отметки внутри квартала сглажены, локальные ямы и насыпи не видны | Для уклонов и объёмов достаточно; съёмка заменяется загрузкой своего `elevation.tif` |
| Профиль строится после плана, а не совместно с ним | Оптимум по «план × профиль» не гарантирован | Уклон уже влияет на план через поле стоимости (§8.5.2) — сильную часть связи учли |
| Не считаем компенсацию тепловых удлинений | Компенсаторы расставляются по интервалам, без расчёта | На стоимость влияет слабо |
| Переход через водные объекты не моделируется | Река — непроходима | Отдельная инженерная задача, вне MVP |
