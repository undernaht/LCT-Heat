# Развёртывание сервиса локально

Пошаговая инструкция: от `git clone` до работающего интерфейса с расчётом.
Конкурсный датасет лежит в репозитории, поэтому ничего докачивать не нужно.

## Что проверено

| Способ | Статус |
|---|---|
| Без Docker (вариант Б) | Проверен целиком на чистом клоне: установка зависимостей, 344 теста, сборка интерфейса, полный цикл через API — расчёт 44 с, S = 12,8605, валидатор 0 ошибок |
| docker-compose (вариант А) | Конфигурация написана по ТЗ §3.2; на машине разработки Docker не установлен, прогон не выполнялся |

Если `docker-compose` по какой-то причине не поднимется, вариант Б даёт тот же
продукт и полностью проверен.

## Требования

| Компонент | Версия | Нужен для |
|---|---|---|
| Python | **ровно 3.11** | расчётный сервис |
| Node.js | 20 или новее | интерфейс |
| Docker + docker-compose | любой современный | вариант А |
| JDK и Maven | 11 или новее | Java-приложение по ТЗ (необязательно) |

Ресурсы: около **2 ГБ** на диске и **4 ГБ** оперативной памяти — расчёт держит
растр 2315 × 1929 ячеек. Интернет нужен для установки зависимостей и для
подложки карты (сам расчёт работает и без него).

> Python именно 3.11: зависимости закреплены версиями (numpy 2.2.1,
> shapely 2.0.6, rasterio 1.4.3), под 3.12 и новее готовых колёс может не быть.

## Шаг 0. Клонировать репозиторий

```bash
git clone https://github.com/undernaht/LCT-Heat.git
cd LCT-Heat
```

## Вариант А. docker-compose — стенд по ТЗ §3.2

Поднимает три сервиса: Java-приложение (Spring Boot 2.6.3), расчётный сервис на
Python и PostgreSQL 15.

```bash
docker-compose up --build
```

Первая сборка занимает несколько минут: скачиваются базовые образы, ставятся
зависимости Python, собирается интерфейс и Java-приложение.

Когда в логе появится `Started HeatApplication`, открыть:

* интерфейс и API — <http://localhost:8080>
* Swagger — <http://localhost:8080/swagger-ui.html>
* расчётный сервис напрямую — <http://localhost:8010/docs>

Остановить: `Ctrl+C`, затем `docker-compose down` (с `-v` — вместе с данными).

## Вариант Б. Без Docker

### Б1. Расчётный сервис (порт 8010)

**Linux / macOS**

```bash
python3.11 -m venv backend/.venv
backend/.venv/bin/pip install -r backend/requirements.txt
backend/.venv/bin/python -m uvicorn app.main:app --app-dir backend --port 8010
```

**Windows (PowerShell или cmd)**

```bash
py -3.11 -m venv backend\.venv
backend\.venv\Scripts\python.exe -m pip install -r backend\requirements.txt
backend\.venv\Scripts\python.exe -m uvicorn app.main:app --app-dir backend --port 8010
```

Установка зависимостей занимает 2–4 минуты. Сервис считается поднятым, когда в
консоли появилось `Uvicorn running on http://127.0.0.1:8010`.

Проверить, не открывая браузер:

```bash
curl http://localhost:8010/health
```

Ответ: `{"status":"ok"}`

### Б2. Интерфейс (порт 5173)

Во **втором** терминале, не закрывая первый:

```bash
npm ci --prefix frontend
npm run dev --prefix frontend
```

Открыть <http://localhost:5173>. Запросы на `/api` интерфейс сам проксирует на
порт 8010 — поэтому расчётный сервис должен быть уже запущен.

### Б3. Java-приложение по ТЗ (необязательно)

Нужны JDK 11+ и Maven. Работает на файловой базе H2 вместо PostgreSQL;
расчётный сервис на 8010 должен быть запущен.

```bash
npm ci --prefix frontend && npm run build --prefix frontend
mvn -f service/pom.xml -DskipTests package
java -jar service/target/heat-network-service-0.1.0.jar \
  "--spring.datasource.url=jdbc:h2:file:./service/target/run/heat;MODE=PostgreSQL" \
  --spring.datasource.username=sa --spring.datasource.password= \
  --heat.data-dir=./service/target/run/projects \
  --spring.web.resources.static-locations=file:./frontend/dist/
```

Интерфейс и Swagger — на <http://localhost:8080>.

## Как убедиться, что всё работает

### 1. Расчёт через интерфейс

1. Открыть интерфейс (5173 или 8080).
2. Перетащить в поле загрузки файл
   `ресурсы/распаковано/ТЗ/Датасет скорректированный.geojson` из репозитория.
   Появится паспорт входа: **17 точек подключения, 488,72 т/ч, 29 участков сети,
   9 камер, 88 ограничений, замечаний к входу нет**.
3. Нажать **«Построить варианты подключения»**. Расчёт занимает около 30–45 секунд.
4. Должно получиться: **три варианта, S = 12,86 / 12,90 / 13,42**, у всех
   «все точки подключены», в панели «Проверка по правилам приложения» —
   **«Нарушений правил приложения нет»**.
5. Кнопка **«Скачать результат»** отдаёт совмещённый GeoJSON по §7 приложения.

### 2. Расчёт из командной строки

```bash
backend/.venv/bin/python backend/case_cli.py \
  --input "ресурсы/распаковано/ТЗ/Датасет скорректированный.geojson" \
  --out result.geojson --png result.png
```

Ожидаемый хвост вывода:

```
v1 (rank 1, порядок nearest_first): S = 12.8605
  длина 1826.2 м, участков 28, камер 14 (58 млн), врезок 0
  стоимость строительства 263.65 млн, штраф 0 млн, итого 263.65 млн
  неподключённых: нет; предельная длина: ok; поднято Ду: 0; минимальность: ok
```

### 3. Независимая проверка результата

Валидатор написан отдельно по тексту технического приложения и пересчитывает
каждое число выхода — длины, расходы, Ду, отступы, углы, стоимость, показатель S:

```bash
backend/.venv/bin/python backend/validate_cli.py \
  --input "ресурсы/распаковано/ТЗ/Датасет скорректированный.geojson" \
  --output result.geojson
```

Прогон по всем девяти наборам сразу (конкурсный и восемь синтетических) —
около 10 минут:

```bash
backend/.venv/bin/python backend/verify_all.py
```

### 4. Тесты

```bash
backend/.venv/bin/python -m pytest backend/tests -c backend/pytest.ini --rootdir=backend -q
```

Ожидаемо: **344 passed, 8 skipped**. Пропускаются тесты прежней модели — им нужен
демо-район, который генерируется отдельно (`data/generate.py`) и в репозиторий
не входит.

Тесты Java-приложения (нужен Maven): `mvn -f service/pom.xml test` — 5 тестов.

## Если что-то пошло не так

**Порт занят.** Расчётный сервис поднимается на любом порту: добавить
`--port 8020`. Для интерфейса тогда поправить `frontend/vite.config.ts` —
в `server.proxy` указан адрес `http://127.0.0.1:8010`.

**`python3.11: command not found`.** Проверить версию: `python3 --version`.
Под 3.12 и новее зависимости могут не собраться — нужен именно 3.11.

**Карта пустая, а панели работают.** Vite сломал web worker MapLibre
предбандлингом. Помогает удалить кеш и перезапустить:
`rm -rf frontend/node_modules/.vite && npm run dev --prefix frontend`.

**Карта без подложки, но объекты видны.** Нет доступа к тайлам OpenStreetMap.
На расчёт это не влияет — вся геометрия и все числа считаются локально.

**Долгий первый расчёт.** Нормально: строится растр всего района. Повторные
расчёты того же проекта идут столько же — кеша результатов нет намеренно,
чтобы числа всегда были честными.

**Ошибка установки `rasterio` или `shapely`.** Почти всегда это неподходящая
версия Python. Проверить, что venv создан именно на 3.11:
`backend/.venv/bin/python --version`.
